## ⚠️ 先读：十个口径陷阱

这些踩过坑，前端务必注意：

1. **评分是 1 分制（0~1），不是百分制。** `total_score: 0.6505` 表示 65.05%，要显示百分比自己 ×100。
2. **收益率字段已经 ×100。** `t1_close_ret: -0.92` 就是 −0.92%，直接加 `%` 即可，**不要再乘 100**。
3. **`/api/watch/stats` 的 `hit_rate` 不能直接当胜率对外展示。** 它有幸存者偏差——新入池的票一命中就进分母，没命中的还挂在 `watching` 不计入。真实值要用"窗口走满的世代"算（44.08% vs 公允 39.05%）。要展示可信数字请用 `by_entry_type` 分组值。
4. **K线的 `adjust` 可能被降级。** 请求 `hfq` 时若区间无复权数据，会自动回退原始价并把 `adjust` 标成 `"none(hfq unavailable)"`。**读响应里的 `adjust` 字段判断实际口径**，别假设等于请求值。
5. **`seal_rate`（封板率）只有近 14 天有值**，更早为 `null`（需盘中数据，日线算不出）。画趋势图会断。
6. **`/api/sentiment/*` 是日频读库，盘中不会变。** 它给的是**最近已收盘交易日**的状态。盘中要看当下阶段用 `/api/hotspot/sentiment`——实测同一时刻两者可能相反（实时"退潮·离场规避" vs 昨收"修复·谨慎试仓"）。
7. **`/api/hotspot/*` 依赖外部 API**，与其他读库接口不同。上游抖动会直接反映到看板，失败返回 **503**（不是 500），前端应据此显示"数据源暂不可用"而非崩掉。
8. **行业粒度不统一。** 2026-08-21 起是东财细分行业（「一般零售」「航运港口」），更早是证监会大类（「C39计算机、通信和其他电子设备制造业」，含 658 只票）。**跨期行业对比会混淆**，建议只展示近期。
9. **`/api/pool-limitup` 的 `pools` 不再包含已结算的池子。** 只有「仍在跟踪」与「近期命中(10自然日内)」两类会被标记。之前把 `settled`/陈年 `hit` 也算作有效，实测虚增一倍（30 只里 15 只是假的）。用新增的 `pool_detail[].is_live` 区分活信号与命中延续。
10. **`/api/pullback/alerts` 是盘中预判，不是确认。** 用 14:45 的实时价算，**尾盘 15 分钟可能拉走或砸穿**。它与 `/api/pullback` 的正式入池是两张表、两个口径，前端不要混为一谈。看 `confirmed` 字段了解历史准确率。

## 五、低位首板池

**盯什么**：低位（距 120 日最低收盘 ≤30%）+ 首板（前 60 日无涨停）+ 非 ST 的票，
入池后跟踪 30 个交易日。

**标签**：30 日内是否**再次涨停**。实测公允命中率 **39.05%**，随机基准 19.87%。

### `GET /api/watch`

| 参数 | 说明 |
|---|---|
| `status` | `watching` / `hit` / `expired` |
| `entry_type` | `solo` 孤板 / `consecutive` 连板 —— **连板组命中率 70.81%，是孤板 34.75% 的两倍** |
| `board_group` | `main` / `other` |
| `exclude_broke` | `true` = 剔除已跌破首板开盘价的票 |
| `order_by` | `live_score`(默认) / `entry_score` / `trigger_date` |
| `since` / `limit` | — |

**关键字段**：

- `trigger_vol_ratio` **首板放量倍数，最有预测力**。实测 <2倍 43.1% / 2-4倍 40.2% / 4-6倍 32.6% / ≥6倍 **18.8%**。**越小越好**，建议 ≥4 标黄、≥6 标红。
- `entry_score` 入池评分（只用首板当天信息，入池后不变）；`live_score` 跟踪评分（含连板加成、跌破打折，每日更新）。列表排序用后者，回溯"当初该不该关注"看前者。
- `flat_days` 低位横盘天数 —— **只展示别排序**，实测与命中率相关性≈0。
- `broke_open_date` 非 null = 已跌破首板开盘价，走弱信号，建议置灰。

### `GET /api/watch/stats`
注意 `hit_rate` 的幸存者偏差（陷阱 3），用 `by_entry_type` 更可信。

### `GET /api/watch/{code}`
多一个 `track` 数组（每日 `ret_since` / `amount_ratio` / `is_limit_up`），可画演化曲线。

> ⚠️ 该接口**从外网访问目前返回 503**（`/api/watch` 和 `/stats` 正常）。
> 服务器本机 `curl 127.0.0.1:8000/api/watch/603207` 返回 200 且数据完整，
> PM2 日志里没有该请求记录 —— 是外层代理/CDN 对 `/{参数}` 形态 URL 的处理问题，
> **不是后端 bug**。联调卡住时先本机验证再排查代理。

## 六B、突破回踩池

**盯什么**：底部横盘 → **涨停启动** → **回调至 MA10 附近**。跟踪 10 个交易日。

**与另两个池的本质差别是「触发时机」**：

| 池 | 触发日 | 标签 |
|---|---|---|
| `/api/watch` 低位首板 | 涨停当日 | 30日内再次涨停 |
| `/api/lowvol` 低位放量 | 放量当日 | T+N 收益率 |
| **`/api/pullback` 突破回踩** | **回调确认日（涨停后2~15日）** | 10日内再涨停 + T+N 收益 |

前两个是「事件当天就入池」，本池是**二次确认**——涨停后先不动，等回调到
MA10 附近才提示。故 `breakout_date`（启动日）与 `pullback_date`（入池日）
是两个不同的日期，**列表默认按 `pullback_date` 倒序**。

**入池条件**（只用回踩日及之前的信息，无未来函数）：
低位（距120日低点 ≤50%）+ 首板（前60日无涨停）+ 非ST，
且回踩日收盘落入 **MA10 ±3%**、相对启动段最高收盘**至少回落 1%**、
**未跌破启动日开盘价**。连板情形从**断板后**起算回踩窗口。

### `GET /api/pullback`

| 参数 | 说明 |
|---|---|
| `status` | **状态机**：`triggered`=已报警 / `armed`=待回踩(未报警) / `missed`=第二波已启动作废 / `failed`=跌破作废 / `expired`=未等到回踩 / `hit`,`settled`=触发后结算。**留空=只返回已报警的**(triggered/hit/settled) |
| `entry_kind` | `limitup`=单根涨停 / `streak`=多根连续阳线 |
| `max_vol20` | **默认 `2.5`（主筛选）**：启动前20日涨跌幅标准差上限，越小越「安静」。近30个交易日实测出票量：≤1.5 约 **4 只/天**、≤2.0 约 **12 只/天**、≤2.5 约 **26 只/天**、不筛 86 只/天。**vol20 为空的行一并排除**（未度量≠合格）。传 `null` 关闭 |
| `first_board_only` | **默认 `false`**：启动段前60日无涨停。实测它只是「安静程度」的弱代理——低波动组里首板与否几乎无差别（T+10 −0.024 vs −0.030），故不再默认过滤，保留备用 |
| `only_hot` | 只看命中热门概念/题材的 |
| `since` | 只看回踩日 >= 该日期的 |
| `max_gain_from_low` | 距120日低点涨幅上限%（入池阈值 50，可再收紧） |
| `exclude_broke` | **默认 `true`**：剔除回踩入池后又跌破启动段首日开盘价的「破位」票。实测破位组 T+10 **−7.74%** vs 未破位 **+4.32%**、命中率 7.49% vs 14.61%，是全池区分度最大的单一维度（占 40.6%，平均回踩后第 4.7 日破位）。传 `false` 可取回，数据仍留库 |
| `rhythm` | **节奏分型** `急`/`中`/`缓`——「若涨停、预计多快」。**建议只用于分组查看，不要当筛选**，理由见下 |
| `order_by` | `pullback_date`(默认) / `breakout_date` / `gain_from_low` / `drawdown` / `max_ret` |

**关键字段**：
- `dist_ma10` 回踩日距 MA10 %（**触发判据**），`dist_ma5`/`dist_ma20` 一并记录
- `drawdown_from_peak` **相对启动段最高收盘的回撤%（真正的回调深度）**
- `drawdown` 相对启动日收盘% —— **连板时此值可能为正**（价格仍高于启动日，
  但已从连板高点回落），判断回调深度请用 `drawdown_from_peak`
- `breakout_boards` 启动段连板数（1=孤板）、`pullback_days` 启动→回踩交易日数
- `breakout_vol_ratio` / `pullback_vol_ratio` / `flat_days` —— **已落库但不参与排序**，见下

> ⚠️ **本池没有评分字段，不要按分排序。** 另两个池的权重都来自实测 IC，
> 本形态**尚未回测验证**，没有样本可依据，任何排序权重都是拍脑袋。
> 待积累足够样本后再做 IC 分档。

#### `rhythm` 节奏分型：急 / 中 / 缓

回答的是**「若涨停、预计多快」**，不是「会不会涨停」。用于设定持有预期：
急型盯 T+1~T+2，缓型要有等两周的准备。

实测 n=13702（hit 1576 + settled 12126）：

| 节奏 | n | 快速涨停(T+1~2)% | 总命中% | 快占命中% |
|---|---|---|---|---|
| **急** | 647 | **11.90** | 26.58 | **44.8** |
| 中 | 7783 | 3.58 | 12.49 | 28.7 |
| **缓** | 5272 | **1.54** | 8.19 | 18.8 |
| *(基准)* | *13702* | *3.19* | *11.50* | *27.7* |

「快占命中」是关键校验：若条件只是普遍抬高命中率，该比例不会变。急组升到
44.8%、缓组降到 18.8%，说明确实在区分**节奏**而非强弱。

判据（只用回踩日及之前信息）：启动段板数 + 相对峰值回撤 + 启动日放量倍数。
时间稳定性已验证——按回踩日分半，急组快速率 10.07% / 13.28%；分季度
6.09%~18.06%，而缓组恒在 1.28%~2.03%，**五个季度从未反转**。

> ⚠️ **两个必读的使用边界**：
> 1. **不要拿它筛票。** 缓组样本是急组的 8 倍，按节奏过滤会砍掉大部分命中。
> 2. **「缓」不是"预计慢慢涨"，是"不具备急涨特征"。** 它是排除法的结果——
>    实测没有任何条件能把震荡组占比拉起来（所有分档都是 4.6%~7.6%），因为
>    震荡型何时涨停由回踩后的题材轮动决定，那信息**不在回踩日的数据里**。
>    缓组总命中率只有 8.19%，里面大部分根本不涨。
>
> 节奏分型改善的是**持有节奏预期，不是胜率**——全池 ret5 仍是 −0.04%。

> ⚠️ **`hit_rate` 无历史基准可比。** 它只是本池自身的观测值，不代表相对随机
> 有 edge。判断 edge 需与同期全市场基准对照（参考：watch_pool 的「30日内
> 再涨停」随机基准是 19.87%，但本池窗口是 10 日，两者不可直接比）。

**跌破启动段首日开盘价只打标不删除**（`broke_date`）：数据永远留库，
只是 **`exclude_broke` 默认 `true`，前端默认看不到**。要取回传 `false`。

之所以「标记而非删除」：watch_pool 实测**物理删除**会误杀 36.5% 的命中票且
删了无法再验证——那是删库，与这里的「默认不展示」是两回事。

### `GET /api/pullback/stats`

`hit_rate` / `avg_hit_days` / `avg_ret5` / `avg_ret10` / `avg_max_ret`，
并按启动段连板数分组（`by_boards`: solo / consecutive）。
**只统计已结算样本**，`watching` 不进分母——否则是幸存者偏差
（watch_pool 实测 44.08% vs 公允 33.90%）。

### `GET /api/pullback/alerts` — **盘中回踩预警（14:45）**

**为什么需要它**：`/api/pullback` 的正式入池要等 **18:30** 收盘后跑完管线，
那时早已收盘、买不进了。而回踩池的价值恰在「**回踩当日尾盘买入、次日二次
启动**」——实测急型中 T+1 涨停占 11.90%，这部分全被错过。

本接口给出 **14:45 用实时价预判**的名单，留出收盘前 15 分钟的下单时间。

| 参数 | 说明 |
|---|---|
| `alert_date` | 预警日，默认最新一天 |
| `rhythm` | `急`/`中`/`缓` |
| `only_fav` | 只看已收藏的 |

**返回按 急→中→缓 排序**，同型按回撤深的优先。

> ⚠️ **这是预判不是确认。** 判据用的是盘中 `last_price` 代替收盘价，
> **尾盘 15 分钟可能拉走或砸穿**，名单里会有一部分收盘时不成立。
> 前端务必区分展示，不要和 `/api/pullback` 的正式入池混为一谈。

| 字段 | 说明 |
|---|---|
| `last_price` | **预警时实时价**（非收盘价），`snapshot_at` 是抓取时刻 |
| `pool_id` | 对应 `watch_pullback.id`，可回查那条 armed 记录 |
| `dist_ma10` / `drawdown_from_peak` | 口径同正式表，但用实时价算 |
| `confirmed` | **次日回填**：收盘后是否真的入池。`null`=尚未回填 |

`confirmed` 是这套机制的**自检指标**——统计它就知道 14:45 这个时点准不准。
长期偏低说明报得太早，应后移。**前端建议把历史准确率显示出来**，否则用户
无从判断该信任多少。

数据源是同花顺实时快照（非 tushare）：`pro.daily(trade_date=今天)` 盘中
返回 0 行，**日线只有收盘后才有**，故盘中预警必须走另一条路。

### `GET /api/pullback/{code}` → 该票最近一次回踩记录，含 `track` 每日跟踪

`track` 每点含 `dist_ma10`，可直接画「回踩后是否站稳均线」的演化。

## 七、情绪历史（日频读库）

**盯什么**：连板梯队驱动的市场情绪，判断「当前环境能不能做」。894 个交易日历史。

> ⚠️ **这组是日频读库接口，盘中不会变**，给的是最近已收盘交易日的数据。
> 盘中实时阶段见 [盘中热点](#八盘中热点) 的 `/api/hotspot/sentiment`。
> 本组的定位是**历史趋势与阶段统计**。

### `GET /api/sentiment/today?date=` — 最近收盘日快照

```json
{
  "trade_date": "2026-09-09",
  "phase": "修复", "stance": "谨慎试仓",
  "zt_count": 48, "zb_count": 27, "seal_rate": 64.0,
  "advance_rate": 0.2027, "height": 5, "ge2": 15, "first_board": 33,
  "phase_hist_ret5": 0.498, "phase_hist_excess5": 0.123, "phase_hist_days": 444,
  "tiers": [
    {"boards": 5, "count": 1,  "codes": ["..."], "names": ["..."]},
    {"boards": 3, "count": 4,  "codes": [...]},
    {"boards": 2, "count": 10, "codes": [...]},
    {"boards": 1, "count": 36, "codes": [...]}
  ]
}
```

- **`phase`** 六阶段之一：冰点 / 启动 / 主升 / 高潮 / 退潮 / 修复（已做 2 日确认，不会天天跳）
- **`stance`** 操作倾向：空仓观望 / 可以进场 / 持股待涨 / 减仓兑现 / 离场规避 / 谨慎试仓
- **`phase_hist_*`** 该阶段历史上的后续表现（实测 894 天）——建议展示成

  比只显示一个标签有用得多
- **`advance_rate` 晋级率**（昨日连板池今日续板比例）是**最核心的指标**
- **`tiers`** 连板梯队，每档带前 10 只个股，可画金字塔

### `GET /api/sentiment/trend?days=60`
历史序列，**按日期升序返回**，前端可直接画图。含 `zt_count`/`zb_count`/`seal_rate`/
`height`/`ge2`/`advance_rate`/`phase`。可用 `phase` 给折线加阶段色带。

| 高潮 | 6 | 0.7% | 374.2 | 10.3 | 0.304 |
| 主升 | 122 | 13.6% | 78.5 | 7.6 | 0.279 |
| 启动 | 189 | 21.1% | 54.3 | 5.9 | 0.230 |
| 修复 | 444 | 49.7% | 54.7 | 5.0 | 0.210 |
| 冰点 | 27 | 3.0% | 27.1 | 4.4 | 0.200 |
| 退潮 | 106 | 11.9% | 44.9 | 4.2 | 0.170 |

```

│ 修复 · 谨慎试仓                          │
```

### ⚠️ 情绪模块的使用边界（实测结论）

- ✅ **可用作风险开关**：冰点后续 T+5 超额 **−1.63**、退潮 **−0.65**（894 天样本）。
  这两个阶段合计占 15% 的交易日，避开它们能改善整体表现。
- ✅ **阶段切换点信号更强**：进入主升 T+5 **+1.16%** vs 处于主升 +0.38%，差 3 倍。
- ❌ **不要暗示"某阶段适合打板"**：实测各阶段涨停股次日收益都在 **1.8~2.0%**，
  阶段对打板**完全没有区分度**（冰点甚至排第二）。
- ⚠️ 高潮仅 6 天、冰点 27 天，这两档统计上很薄，展示时不宜过度解读。

## 八、盘中热点

**与情绪组的根本区别**：这组**不读库**，直接调同花顺 API + 60秒缓存，**盘中实时刷新**。
多客户端共享同一份缓存——10 个人每 30 秒轮询，对上游仍是每分钟一次请求，不会放大。

### `GET /api/hotspot/overview` — 看板首屏（推荐）
一次取全：涨停数/最高板/连板家数 + 概念榜 + 题材榜 + 涨停 Top20 + 人气榜。
避免前端多次往返，各分量共享同一份缓存。

### `GET /api/hotspot/sentiment` — **盘中实时情绪阶段**

用当下涨停/跌停现算，**这是盘中该看的那个**：

```json
{"as_of":"2026-09-11 21:52:40",
 "phase":"退潮","stance":"离场规避",
 "zt_count":40,"dt_count":21,"zt_dt_ratio":1.905,
 "first_board":33,"ge2":7,"height":4,
 "advance_rate":0.0784,                    // 晋级率:昨日连板池今日续板比例
 "phase_hist_excess5":-0.653,"phase_hist_days":106,
 "prev_phase":"修复","prev_zt_count":48}   // 昨收对照,便于看变化
```

`advance_rate` **晋级率是最核心的指标**。上例 0.078 意味着昨日连板池今日几乎全断板——这就是退潮。
不做 2 日确认（那是为消除历史序列跳变，盘中本就该看当下）。

### `GET /api/hotspot/themes?min_count=2` — 今日主线

把当日涨停股的「涨停原因」拆词聚合。原因串形如 `800G光引擎+CPO+AI算力+营收增长`，
**出现最多的标签就是当日主线**。这是目前唯一能拿到的真正题材维度。

```
业绩增长  6只  最高2板   机器人  2只   AI应用  2只   商业航天  2只
```

### `GET /api/hotspot/concepts?limit=30&order_by=pct|turnover`
390 个概念板块实时行情。**涨幅与成交额同时靠前才是真有资金进场**，
只涨不放量多是脉冲。

### `GET /api/hotspot/limitup` / `GET /api/hotspot/limitdown`
实时涨停池（连板数、封单金额、题材标签、首封时间）/ 跌停池（含首末跌停时间）。

### `GET /api/hotspot/ladder?days=1`
官方连板天梯，近 30 日。含 **`seal_nextday`（次日是否封板）**——官方给出的晋级结果，比自算准。

### `GET /api/hotspot/auction?codes=600519,002636` — **集合竞价**

对「尾盘买入、次日卖出」打法最关键的开盘信号：

```json
{"name":"金安国纪","auction_price":76.0,"auction_pct":-0.59,
 "unmatched":-642.0,          // 未匹配量,负=卖压
 "vs_yesterday_pct":2.31,     // 竞价量占昨日成交比
 "volume_ratio":3.03}
```

**昨日尾盘买的票今早竞价强不强，直接反映有无资金承接。**
上例 `unmatched=-642` 是卖压，涨幅 −0.59%，说明接力资金不足。
`codes` 传 6 位代码即可，内部自动补 `.SH`/`.SZ`。

> 这是**实时**直调、不落库、只能按代码查。要看**全市场竞价总额**或**历史**，用 [`/api/auction`](#十四集合竞价)。

### `GET /api/hotspot/auction/benchmark`
短线风向标——官方筛选的竞价标的，自带题材 `tags`。

### `GET /api/hotspot/hot?kind=hot|skyrocket`
人气榜 / 飙升榜，含 `rank_change` 与 `rank_trend`（up/down/flat）。

## 十、收藏

**本项目唯一一组写接口。** 其余所有接口都是只读的——业务数据（行情/因子/
三个监控池）由 engine 跑批独占写入，API 不碰；收藏是用户行为数据，
不由跑批产生，故单独开了 `watch_favorite` 一张表允许 API 写。

**按股票代码收藏、跨池共享**：收藏的是「这只票」，不是「某次入池事件」。
三个监控池共用同一份收藏，同一只票多次启动也只有一条记录。
当前不区分用户（系统单人使用且 API 无认证）。

### `GET /api/favorite` — 收藏列表

按收藏时间倒序。字段：`id` / `code` / `name`（收藏时的名称快照）/ `note` /
`created_at` / `updated_at`。

### `GET /api/favorite/codes` — 只返回代码数组

`["600001", "603138", ...]`。**给列表打星标用**——前端拉一次做 O(1) 查表，
不必为每行再查一次收藏状态。

### `POST /api/favorite` — 新增收藏

请求体 `{"code": "600001", "name": "可选", "note": "可选备注"}`。
`name` 不传则服务端从 `stock_basic` 自动补全（查不到再从池子里取）。

> **幂等**：重复收藏同一只票不报错，而是更新 `note`/`name` 后返回原记录。
> 前端重复点击或网络重试都不会产生重复行或 500。

### `DELETE /api/favorite/{code}` — 取消收藏

删不存在的返回 **404**，便于前端区分「本来就没收藏」与「删成功」。

### `PATCH /api/favorite/{code}` — 修改备注

请求体同 POST；只更新 `note` 和 `name`。不存在返回 404。

### 在监控池里筛收藏

**三个监控池都支持** `only_fav=true`，共用同一份收藏：

| 池 | 用法 |
|---|---|
| 回踩池 | `GET /api/pullback?only_fav=true` |
| 低位首板池 | `GET /api/watch?only_fav=true` |
| 低位放量池 | `GET /api/lowvol?only_fav=true` |

与各池其他筛选（`max_vol20` / `exclude_broke` / `order_by=hot_score` 等）可叠加。

> 注意 `only_fav` 按**代码**匹配，所以同一只票的多次启动都会命中同一份收藏。

### ⚠️ CORS：写接口需要预检

`POST`/`DELETE`/`PATCH` 带 `Content-Type: application/json` 属**非简单请求**，
浏览器会先发 `OPTIONS` 预检。服务端 `allow_methods` 已包含
`GET,POST,DELETE,PATCH,OPTIONS`、`allow_headers` 含 `Content-Type`。

> 2026-09-15 修复：此前 `allow_methods` 写死 `["GET"]`（API 还纯只读时留下的），
> 导致浏览器写请求全被预检挡下，而 **curl 直连完全正常**——只有浏览器挂，
> 极易误判成接口逻辑 bug。

## 十一、池内涨停

把**三个监控池里今日涨停（或曾摸过板）**的标的单独列出来。
数据来自 `limitup_stock`：盘中每 10 分钟由 `fetch_limitup_live` 刷新
（涨停池 + 炸板池），盘后 18:30 由 `fetch_hotspot` 定格。

### ⚠️ 「涨停」有两种状态，必须区分展示

| 字段 | 含义 |
|---|---|
| `is_sealed_now = true` | **当前封着** |
| `is_sealed_now = false` | 今天摸过板，但**现在没封住**（炸板） |
| `open_times` | 今天炸过几次。**当前封着也可能非零**（封→炸→再封） |

`open_times` 是判断「封板结不结实」的关键——封单小、炸过多次的票更容易再炸。
这也是当初单独接炸板池的理由：**涨停池根本不返回该字段**。

### `GET /api/pool-limitup`

| 参数 | 说明 |
|---|---|
| `trade_date` | 指定交易日，默认取数据里最新一天 |
| `pool` | 只看某池：`pullback` / `watch` / `lowvol` |
| `sealed_only` | 只看当前封着的（排除炸板） |
| `since_days` | 只算最近 N 天入池的，**默认 30**；`0`=不限 |
| `live_only` | 只看仍在跟踪的活信号，排除「命中后延续」 |

**排序**：活信号在前 → 封着的在前 → 连板多的在前 → 炸板次数少的在前。

同一只票在多个池里**只返回一行**，`pools` 列出它命中了哪些池。
`in_favorite` 标明是否已收藏。

### ⚠️ 池内记录只含「仍在跟踪」与「近期命中」两类

**已结算的历史样本不再标记**（`settled` / `expired` / 陈年 `hit`）——它们的
观测窗口早已走完，今天涨停与当初那次入池无关。

修复前曾把终态也算作有效：实测 2026-09-18 标出 30 只，其中 **15 只是虚假
标记**（虚增一倍）。pullback 池尤甚——窗口内 1169 个代码有 700 个是终态，
因为 `settled`(12030条) 是 `triggered`(480条) 的 25 倍。

口径规则：**活跃态按入池日筛，终态按结束日筛**。原 bug 正是拿 `trigger_date`
（入池日）去筛一个早已结束的事件——入池日新不代表事件还活着。

### `pool_detail`：区分「新信号」与「命中后延续」

只看 `pools: ["watch"]` 时，两者长得一模一样——上面那个 bug 藏了很久正因
如此。故每条记录的来源一并返回：

```json
"pools": ["watch"],
"pool_detail": [
  {"pool":"watch","status":"watching","entry_date":"2026-09-10",
   "hit_date":null,"is_live":true}
]
```

| 字段 | 说明 |
|---|---|
| `status` | `watching`/`triggered`=仍在跟踪，`hit`=近期命中 |
| `entry_date` | 入池日（回踩池是 `pullback_date`） |
| `hit_date` | 命中日，仅 `status=hit` 有值 |
| `is_live` | `true`=活信号，`false`=命中后延续期 |

**命中后 10 个自然日内**再涨停仍算同一波延续（`is_live=false`）。保留它是
因为这类往往是「跟随第二波」：实测古越龙山 09-16 命中、09-18 又涨停。
更早的（如 08-28 命中距今 21 天）则已剔除。

**前端建议**：把 `is_live` 用上，显示「回踩池 09-17报警」vs「首板池 09-16
已命中」，两者的操作含义完全不同。

### `GET /api/pool-limitup/stats`

```json
{"trade_date":"2026-09-15","total_limitup":52,"in_pools":20,
 "sealed":12,"broken":8,
 "by_pool":{"pullback":16,"watch":8,"lowvol":1},
 "live_signals":16,"recent_hits":4,
 "snapshot_at":"2026-09-15T13:00:03","is_stale":false}
```

`live_signals` / `recent_hits` 把 `in_pools` 拆成「仍在跟踪」与「命中后延续」
两类，对应 `pool_detail` 里的 `is_live`。

> `is_stale=true` 表示数据不是当天的（比如周末查），
> 前端应提示「非当日数据」，避免把上一个交易日的涨停当成今天的。
> `snapshot_at` 是数据抓取时刻，可据此判断新鲜度。

## 十二、板块轮动

`GET /api/rotation` —— 回答「**热度在哪个板块**」「**这条主线走到第几天**」。

### ⚠️ 与 `/api/hotspot` 的分工（两者都叫"热点"，但不是一回事）

| | `/api/hotspot` | `/api/rotation` |
|---|---|---|
| 数据源 | 同花顺**实时直取**，不读库 | 读库内 `concept_daily` **历史序列** |
| 回答 | 此刻哪个板块在涨 | 这个板块**连涨了几天**、在升温还是退潮 |
| 刷新 | 盘中 60 秒 | 日频（盘后 `fetch_hotspot` 落库后更新） |

**单日快照区分不了「一日游」和「持续主线」**——这正是本接口存在的理由。
实测 2026-09-18 注册制次新股 +7.30%，次日回落到 +0.26%；
而医药系（重组蛋白/CRO/细胞免疫）连续 4 日逐级抬升。
**两者在单日榜单上长得一模一样**，只有拉出序列才分得开。

### 🔴 本接口不做轮动预测

轮动由**催化事件**（政策/业绩/消息）驱动，催化在发生前不存在于价格数据里。
`stage` 是对**当前所处位置**的规则判定，不是对**下一个热点**的预测。

### 请求参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `window` | 8 | 回看交易日数（3~60） |
| `limit` | 20 | 返回概念数 |
| `dedup` | true | 同族概念去重（成分股重叠≥15%） |
| `include_broad` | false | 是否含宽基/交易属性标签（融资融券等） |
| `stage` | — | 只看某阶段：`升温`/`持续`/`退潮`/`一日游`/`刚启动` |

### 五个阶段的含义

| stage | 判据 | 前端含义 |
|---|---|---|
| `刚启动` | 最后一天突然大涨，此前安静 | **尚待验证**的当日异动 |
| `升温` | 近3日均相对全市场中位数 +0.8pp 以上 | 已被验证 2~3 天的趋势 |
| `持续` | 无明显方向（兜底） | 平稳 |
| `退潮` | 相对中位数 −0.8pp 以下 | 资金在撤 |
| `一日游` | 脉冲单日撑起涨幅，其后哑火 | **假信号**，别追 |

> **`升温`/`退潮` 判的是相对全市场中位数的偏离，不是绝对涨幅。**
> 实测 390 个概念有 90% 的 delta 为正（大盘整体在涨），
> 用绝对阈值会把半数概念标成「升温」——那测的是大盘不是概念。
> 响应里的 `median_delta` 如实返回当日基准，前端可据此理解判定口径。

### 响应

```json
{"trade_date":"2026-09-21","days_available":8,"window":8,
 "median_delta":1.05,
 "dates":["2026-09-10","...","2026-09-21"],
 "stage_counts":{"升温":33,"持续":270,"退潮":56,"一日游":4,"刚启动":1},
 "concepts":[
   {"thscode":"885955.TI","name":"重组蛋白",
    "pct_chg":4.76,"avg3":2.89,"avg_prev3":0.80,
    "turnover_share":0.074,"share_trend":0.021,"rank_pct":2,
    "stage":"升温","stage_reason":"近3日均2.89%，相对全市场 +1.04pp",
    "up_days":4,"max_day_pct":4.76,
    "peers":[],"peer_count":0,
    "series":[{"trade_date":"2026-09-10","pct_chg":-2.25,
               "turnover_share":0.041,"rank_pct":367}]}],
 "themes":[{"theme":"3D打印","zt_count":2,"max_boards":1,
            "consec_days":1,"is_new":true}],
 "note":"仅 8 个交易日的概念历史…"}
```

**排序用 `avg3`（近3日均涨幅）而非当日涨幅**——单日榜首常是脉冲，
三日均能把持续走强的主线顶上来。

### `peers`：同族概念去重

医药系实测 CRO概念×减肥药成分重叠 **23%**、细胞免疫×创新药 **15%**。
不去重会让榜单被同一条主线刷屏，**看着像 6 个热点、实际是 1 个**。
去重后只留最热的作代表，其余进 `peers`，`peer_count` 是折叠数。
传 `dedup=false` 可看未折叠的原始榜单。

### `series`：画热力图

按日**升序**，前端可直接横排成矩阵。轮动一眼可见：

```
概念              09-16  09-17  09-18  09-21
重组蛋白           1.28   1.65   2.26   4.76   ← 逐日抬升 = 主线
注册制次新股        1.85   0.24   7.30   0.26   ← 单日脉冲 = 一日游
```

### ⚠️ 数据限制：概念历史只有 8 个交易日

`concept_daily` 自 **2026-09-10** 起逐日积累，**历史无法回补**
（同花顺只提供当前快照，`limit_up_reason` 全表 52507 行仅 464 行有值）。

- `days_available` 如实返回可用天数——**没有分母的序列无法解读**
- 不足 6 日时 `note` 会显式告警，趋势与阶段判定不可靠
- **`stage` 未经预测力验证**（8 天做不了分档检验），仅供观察展示，
  **不参与任何选股决策**。要验证「热门概念能否提升胜率」至少再等 1~2 个月

> 与 `hot_score`（回踩池的概念热度排序）同一约束：热度只排序、不决策。

## 十三、LLM复盘

DeepSeek 对已有数据的**翻译**——把 K 线序列 + 算好的指标写成人话，
省去逐只读表的时间。**只作展示，不参与选股决策，不产生新的买卖依据。**

### ⚠️ 两类接口性质完全不同

| | `GET /api/review` | `POST /api/review/analyze` |
|---|---|---|
| 数据 | 读 `llm_review` 表 | **实时调 DeepSeek** |
| 耗时 | 毫秒 | **10~20 秒** |
| 成本 | 0 | **每次计费** |

盘后管线（第7步，约 18:35）会把当日触发的票批量跑完落库，
**正常用 GET 即可**。POST 是给「想看某只池外的票」「想重新分析」用的。

### `GET /api/review`

| 参数 | 默认 | 说明 |
|---|---|---|
| `trade_date` | 最新有复盘的交易日 | |
| `kind` | — | `stock` / `concept`，不传则都返回 |

```json
{"trade_date":"2026-09-22",
 "concept":{"kind":"concept","content":"医药链最扎实——重组蛋白、细胞免疫治疗…","model":"deepseek-chat"},
 "stocks":[{"kind":"stock","code":"600516","name":"方大炭素",
            "content":"方大炭素距120日低点仅+12.7%，处低位。9月15-18日四阳累计+8.7%…",
            "created_at":"2026-09-22T18:35:12"}],
 "total":12,
 "note":"LLM 对已有数据的翻译,只作展示…"}
```

`concept` 每日一条（板块轮动），`stocks` 是当日触发的回踩池个股。

### `GET /api/review/stock/{code}`

某只票的历史复盘，按时间倒序——用于回看「上周它怎么说的」。

### `POST /api/review/analyze`

| 参数 | 默认 | 说明 |
|---|---|---|
| `code` | 必填 | 股票代码 |
| `trade_date` | 该票最近一次回踩日 | |
| `force` | false | **true=强制重算（重复计费）** |

```json
{"code":"600516","name":"方大炭素","trade_date":"2026-09-22",
 "content":"…","model":"deepseek-chat","cached":true,
 "pullback_date":"2026-09-22","status":"triggered"}
```

> 🔴 **默认幂等，前端务必依赖这一点。** 同一只票同一天已有结果就直接返回
> `cached=true`，不调模型。**如果在渲染逻辑里无脑调 POST，没有这层会按次烧钱。**
> 只有用户明确点「重新分析」才传 `force=true`。

**前端必须做加载态与防连点**——这个接口要 10~20 秒。

| 状态码 | 含义 |
|---|---|
| 404 | 该票在回踩池中无记录（不是池内票不能分析） |
| 422 | K线数据不足 |
| 503 | 模型调用失败，或 `DEEPSEEK_API_KEY` 未配置 |

> 失败时**不落库**，不会把空内容写进表。

### 内容的可信边界

**能信的**：引用的日期、涨跌幅、放量缩量方向均来自库内，可逐条回查核对。
指标值（位置/量比/回撤）由规则算好后传给模型，不是它自己算的。

**不能信的**：模型对量价含义的解读，本质是《平庸时刻》文档口径的复述。
prompt 已硬性要求：二义的组合必须说明是二义、不预测涨跌、不给买卖建议。
如果输出里出现了目标价或「建议买入」，那是模型越界，请反馈。

> ⚠️ 注意回踩形态的票**绝大多数都是「价跌量缩」**（回调本就是跌+缩量），
> 所以这个标签本身没有区分度，别拿它当筛选依据。

## 十四、集合竞价

开盘集合竞价（9:25 撮合结果）。**每个交易日 9:30 落库，约 9:34 可查**；休市日不产生数据。
**历史自 2026-09-23 起**（数据源无历史接口，之前的补不回）。

**总量和个股是分开的接口，互不包含**：

| 接口 | 返回 |
|---|---|
| `GET /api/auction/market` | 全市场汇总，每日一条 |
| `GET /api/auction/stocks` | 某日个股明细（分页） |
| `GET /api/auction/stocks/{code}` | 单只票的历史 |

> 与 `/api/hotspot/auction` 的区别：那个是**实时**按代码查、不落库；本接口读库、有历史和全市场汇总。

### ⚠️ 单位

- **金额是「元」**，不是亿、不是万。`total_amount: 13763310811.72` = **137.63 亿**，展示时自己 ÷1e8。
- **量是「手」**（1 手 = 100 股）。
- 百分比字段（`auction_pct` / `turnover_pct` / `vs_yesterday_pct` / `chg_pct`）**已 ×100**，直接加 `%`。

### `GET /api/auction/market` — 全市场汇总

| 参数 | 默认 | 说明 |
|---|---|---|
| `days` | 30 | 最近 N 个有数据的交易日 |
| `start` | — | 起始日（含），传了则忽略 `days` |
| `end` | 最新 | 截止日（含） |

按日期**倒序**：

```json
[{"trade_date":"2026-09-23",
  "total_amount":13763310811.72,   // 全市场竞价额(元) = 137.63亿
  "sh_amount":6183182413.36, "sz_amount":7440074013.36, "bj_amount":140054385.0,
  "chg_pct":null,                  // 较上一个交易日变化%,无前一日时为 null
  "n_codes":5554, "n_fetched":5554,
  "complete":true,                 // false = 当日抓取不完整,总额偏低,别拿来比
  "n_traded":5464,                 // 竞价有成交的只数
  "n_up":1866, "n_down":2617,      // 竞价涨/跌家数(不含无成交)
  "n_limit_up":5, "n_limit_down":9}]
```

> 🔴 **`complete=false` 的那天总额不可信**（部分批次抓取失败，漏了票），画趋势图时应标注或跳过，否则会看到一个假的「竞价骤降」。

### `GET /api/auction/stocks` — 某日个股明细

| 参数 | 默认 | 说明 |
|---|---|---|
| `trade_date` | 最新有数据的交易日 | |
| `codes` | — | 逗号分隔 6 位代码，只看这些票 |
| `limit_up_only` / `limit_down_only` | false | 只看竞价涨停 / 跌停 |
| `order_by` | `amount` | `amount` 竞价额 / `pct` 竞价涨幅 / `unmatched` 未匹配量 / `volume_ratio` 量比 / `vs_yesterday` 占昨日成交比 / `turnover` 竞价换手 |
| `asc` | false | 升序 |
| `limit` / `offset` | 100 / 0 | 分页，`limit` 上限 1000 |

```json
{"trade_date":"2026-09-23", "total":5554,     // 筛选后总数,不是本页条数
 "items":[{"code":"002614","name":"奥佳华",
           "auction_price":7.57, "auction_pct":10.03,
           "auction_volume":138203.0,         // 手
           "auction_amount":104619671.0,      // 元
           "unmatched":-44290.0,              // 未匹配量(手),正=买单未成交,负=卖单未成交
           "turnover_pct":3.13, "vs_yesterday_pct":114.83, "volume_ratio":3.34,
           "pre_close":6.88, "is_limit_up":true, "is_limit_down":false}],
 "note":null}
```

- **`unmatched` 要结合价格看**：竞价涨停且 `unmatched` 为正 = 涨停价上还有买单没买到，封得牢；
  为负（如上例奥佳华）= 涨停价上卖单都没消化完，**看似涨停开盘，实则没封住**。跌停反之。
- 无成交（停牌等）的票各字段为 `null`，**无论升序降序都排在最后**。
- 全市场每天约 5500 只，请分页取，别一次拉全。

### `GET /api/auction/stocks/{code}` — 单只票历史

| 参数 | 默认 | 说明 |
|---|---|---|
| `days` | 20 | 最近 N 条 |

按日期倒序返回个股记录数组（字段同上），无记录返回 `[]`。

### 口径说明

- **竞价涨跌停**按「竞价价 ≥ 涨停价 / ≤ 跌停价」判定，涨跌停价按板块四舍五入到分：主板 10%（**ST 也是 10%**，2025-07 起）/ 创业板·科创板 20%（含 ST）/ 北交所 30%。
- 名称以 `N`/`C` 开头的新股（上市前 5 日，无涨跌幅限制）**不参与涨跌停判定**，恒为 false。
- 代码范围是**前一交易日库内的全部代码**，当日上市的新股不在内。
